# ADR-0007 Web 模式：dsh-remote 直出启动页，浏览器零安装使用

- 状态：已接受（2026-08-14）
- 依据：[ADR-0004](ADR-0004-token-proxy.md)（令牌反代）、[ADR-0006](ADR-0006-pairing-code-and-tls.md)（配对码）；阶段 2 实录（[06](../06-phase2-pairing-tls.md)）

## 背景

v0.2.0 的使用前提是先在手机上安装 App（APK 或 iOS 构建），启动页再配对进主机。但启动页做的事情——健康检查、兑码、跳转种下 Cookie——全部是纯浏览器能力，Capacitor 壳只是它的载体。临时借用、桌面浏览器、不便装包的设备（如他人手机、受限设备）都被"必须先装 App"挡在门外。

dsh web 本身是完整 Web UI，dsh-remote 已经是唯一公网/局域网入口；让代理在未授权时直接吐出启动页，浏览器打开 `http://<主机IP>:3081/` 输入 6 位配对码即可进入，与 App 内体验一致。

## 决策

1. **代理直出启动页（Web 模式）**：dsh-remote 新增启动页服务能力——
   - 未授权 `GET /`（及 `/index.html`）：启动页存在时返回启动页（200），否则维持 401；`GET /launch` 始终返回启动页（供已登录用户更换主机）。
   - 页面来源解析顺序：`DSH_LAUNCHER=<路径>` 显式指定 → 仓库布局默认位 `proxy/../app/www/index.html` → 找不到则关闭并在启动日志明说。`DSH_LAUNCHER=off` 强制关闭（恢复纯 401 行为）。
   - 安全边界不变：启动页是静态页、不含秘密；`/api`、WebSocket、UI 资产仍需令牌；`/pair` 限速不变。未授权访客看到的是一个连接界面，不泄漏任何上游内容。
2. **启动页自适应两种载体**：同一份 `app/www/index.html` 同时服务 App 与浏览器。以 `window.Capacitor` 是否存在区分载体：浏览器（Web 模式）下主机地址取 `location.origin`，地址输入框隐藏，用户只需填 6 位配对码；App 内行为不变。页面顶端加 `<!-- dsh-remote launcher -->` 注释标记，作为冒烟测试的稳定断言点。
3. **冒烟矩阵扩展**：`verify-proxy.mjs` 将"未授权 GET / → 401"改为"未授权 GET / → 启动页（200，含标记，非上游 UI）"，新增 `/launch` 用例；CI 增加 `DSH_LAUNCHER=off` 变体（第三个代理实例，curl 断言未授权 GET / → 401）。

## 后果

- 零安装路径成立：浏览器（手机/桌面）打开代理地址 → 输配对码 → 进入 dsh UI，全程不碰应用商店与签名。App 仍是常驻、全屏、系统级体验的最优载体，两条路径共用同一配对与安全模型。
- 被否决方案：
  - **启动页嵌进 dsh-remote.mjs 单文件**：代理保持单文件可拷，但 HTML 双份维护必然漂移，否决。
  - **独立静态服务器托管启动页**：又多一个进程与端口，违背"主机侧两条命令"的部署简单性，否决。
  - **未授权 `/` 302 到 `/launch`**：多一跳且对 WebView 内的首次渲染无收益，直出更简单，否决。
- 遗留：Web 模式下"已保存的主机"存在浏览器 localStorage（按源隔离），与 App 内互不可见——符合预期，不处理。扫码配对链接（阶段 3 项）在 Web 模式下天然成立（链接即代理地址），届时一并验证。

## 取代关系

细化 ADR-0004 的代理职责边界（增加静态启动页服务）；不改变 ADR-0002/0004/0006 的架构与安全判断。
