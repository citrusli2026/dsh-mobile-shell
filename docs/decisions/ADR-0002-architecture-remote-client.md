# ADR-0002 总体架构：远端客户端（瘦客户端壳），否决端上移植

- 状态：已接受（2026-08-14）
- 依据：[03-feasibility-analysis.md](../03-feasibility-analysis.md)

## 背景

移动版的三条硬约束：功能保持不变、用户直接下载即用、开源。上游架构事实（`01-project-analysis.md` F1–F7）：浏览器已是纯瘦客户端，全部能力在主机侧执行，模型调用走远端 API；主机无认证层；前端无移动适配。

## 决策

1. **架构**：移动 App = 原生壳 + 复用现有 React Web 前端，连接用户自托管的 `dsh web` 主机；不在手机上运行 Node/插件树。
2. **壳技术**：Capacitor（MIT）。v0 用 `server.url` 服务器渲染模式（前端资产由主机伺服，前后端版本恒一致，客户端零改动）；内置资产离线壳（A2）推迟到阶段 3。
3. **认证**：阶段 2 必须解决。首选向上游提交可选 token 认证 PR；若上游不接受，以 cordis patch/bundle 外挂认证代理插件兜底；文档同时提供 Tailscale/反代方案。
4. **分发**：Android 走 GitHub Releases APK（+国内镜像）；iOS 走 TestFlight/App Store。仓库固定对接上游 npm release 版本，不追 main。

## 后果

- 功能完整性由"执行留在主机侧"保证，App 自身不含执行引擎；"下载即用"的含义是下载壳 + 连接一台主机，文档必须提供主机一键部署向导，否则新用户无法上手。
- 被否决方案：
  - **端上移植（B）**：iOS 禁止 fork/exec 任意子进程，shell/终端/LSP/MCP 等能力无法实现，直接违反"功能保持不变"；Android 侧需捆绑 Node、交叉编译 node-pty/koffi、应对商店政策，工程量与风险远超收益。Termux 手动运行作为极客备选写进文档即可，不产品化。
  - **纯 PWA（C）**：iOS 推送/后台/安装引导受限，不构成"下载一个 App"；保留为零成本副产品（补 service worker）。
  - **React Native 重写**：需重写全部 `ui-*` 包并永久跟随上游 UI 演进，否决。
  - **托管云优先（D）**：改变信任模型与开源定位，转为远期可选。
- 遗留风险与缓解见可行性文档第 7 节；其中"上游破坏性变更"由版本钉扎 + 快照测试缓解。

## 取代关系

无。若未来上游提供官方移动/远程客户端或认证能力，应新增 ADR 重新评估壳层与认证方案。
