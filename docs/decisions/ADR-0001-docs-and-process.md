# ADR-0001 文档位置与过程记录方式

- 状态：已接受（2026-08-14）

## 背景

需求方要求：移动版项目"每一步都要提交"，并且"写决策记录文档，新建 docs 目录"记录实现过程。

上游仓库已有 `docs/` 目录，但它受《docs/AGENTS.md 文档标准》严格约束：文档分级（tutorial/reference）、一词一址、字数预算（`verify-doc-budgets`）、中英文配对（i18n 契约）、机器可校验链接（`verify-md-links`）等多道门禁。过程性、推理性的内容按上游规范属于 `.agents/notes/`（Agent Notes），不属于 `docs/`；把探索过程写进上游 `docs/` 会同时违反"一词一址"分级规则并触发预算与翻译配对门禁。

## 决策

移动版项目的全部过程文档放在上游仓库内的新顶层目录 `docs/`：

- `docs/` 存分析文档与本工作约定；
- `docs/decisions/` 存 ADR；
- 不改动上游 `docs/`、`.agents/notes/` 与任何门禁清单（如 `scripts/doc-budgets.manifest.json`）。

后续在 GitHub 建立独立开源仓库时，`mobile/` 目录整体迁移过去，文档历史随之保留。

## 后果

- 优点：过程文档不触碰上游文档门禁，提交可以保持小步快走；迁移到独立仓库时自包含。
- 代价：这些文档不受上游 `verify-md-links` 等门禁保护，链接失效靠自觉维护。
- 被否决方案：直接写入上游 `docs/`（违反分级与预算门禁）；写入 `.agents/notes/`（语义上是"给维护者的决策便签"，且归档后冻结，不适合作为面向未来开源社区的规划文档）。
